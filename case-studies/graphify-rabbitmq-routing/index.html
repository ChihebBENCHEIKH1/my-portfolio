How to trace RabbitMQ publishers and consumers across repositories

By Chiheb Ben Cheikh

Before changing a RabbitMQ routing key, find the code that publishes it, the service that binds it and the branch that handles it. Here is a two-service Kotlin example you can run locally with Graphify.

Run the example

The orders service publishes orders.events.completed after an order completes. The billing service declares the key in its bindings and dispatches the event to invoice creation. The example needs Git, Python 3.10 or newer and a shell. Graphify reads the source files, so you can run the query with no RabbitMQ server or Kotlin build.

git clone https://github.com/ChihebBENCHEIKH1/graphify.git
cd graphify/examples/rabbitmq-routing
python3 -m venv .venv
.venv/bin/python -m pip install graphify-cli==0.1.0

export GRAPHIFY_ROOT="$PWD"
export GRAPHIFY_CACHE="$PWD/out"
.venv/bin/graphify root
.venv/bin/graphify build --summary "$GRAPHIFY_CACHE/ARCHITECTURE_GRAPH.md"
.venv/bin/graphify key orders.events.completed

graphify root should show the example directory containing orders and billing. The build writes the graph and Markdown summary into out/.

Read the source locations

Graphify reports one publishing call site and two kinds of evidence for the billing subscriber.

  • Publisher. OrdersUseCase.kt:7 calls sendOrderCompleted. The broker method publishes with the routing key and passes an OrderCompleted payload.
  • Binding. BillingRabbitMQFactory.kt:8 lists the key. Graphify labels this evidence queueBind.
  • Dispatch. BillingMessageHandler.kt:9 routes the same key to invoice creation. Graphify labels this evidence dispatch.

The binding and dispatch lines both describe the billing service. To consume the source locations in a script or review check, add --json before the subcommand.

.venv/bin/graphify --json key orders.events.completed

Check the scope before renaming a key

Inspect the publisher, binding, handler and payload together. A rename in this example touches both repositories. In a deployed application, also check the actual queue bindings and rollout order. Graphify infers the edges from source conventions, including the typed broker method, the factory key list and the dispatch branch shown here. Dynamically constructed routing keys and runtime-only bindings can fall outside that analysis.
