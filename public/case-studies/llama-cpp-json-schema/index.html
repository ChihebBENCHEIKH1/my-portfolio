Preserving JSON Schema constraints in llama.cpp

By Chiheb Ben Cheikh · Founder, BiancoToro Technologies · PR status checked 14 November 2026

A valid escaped hyphen in a JSON Schema pattern could cause llama.cpp’s grammar converter to discard that pattern and fall back to an unconstrained string.

The problem

Three parts of the grammar pipeline disagreed. The grammar parser accepted an escaped hyphen, the character-class builder could emit one, but gbnf_escape_length() rejected it during JSON Schema conversion.

That inconsistency meant a pattern such as ^[a-z\-]+$ could reach the unsupported-pattern fallback. The conversion produced a warning rather than stopping, making the lost constraint easy to miss.

The recorded reproduction

pattern ^[a-z\-]+$ is not supported
(unsupported escape in character class: \-), accepting any string

My contribution

I added the missing hyphen case to the escape-length function and a comment connecting it to the parser’s accepted escapes.

I added regression tests and changed an older unsupported-pattern test to use a lookahead. Otherwise, fixing the hyphen case would have made that older test stop checking an actually unsupported pattern.

Verification and scope

The pull request records the new tests failing without the fix and passing with it, along with the grammar and chat test commands used for verification.

I contributed this fix to llama.cpp, and pull request #29127 is merged. The linked PR documents the exact schema pattern and tests used for this change.

The engineering lesson

Parser, serializer and validation paths need to agree on their accepted syntax. A silent fallback can turn a small disagreement into a loss of constraints. A regression test should check the preserved behavior and keep the fallback path covered separately.
