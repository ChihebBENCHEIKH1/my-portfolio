How I evaluated RAG retrieval on financial filings

By Chiheb Ben Cheikh

In FinRAG, plain BM25 keyword search retrieved the evidence more often than either dense or hybrid search on the development set. It still missed the evidence on over a quarter of the answerable questions in the held-out test set.

What I measured

I built a question-answering prototype over five public 10-K filings. I wrote the evaluation protocol before building the system and kept the development and test sets separate.

Recall@5 measures how often a question’s reference evidence appears in the five highest-ranked chunks. It measures evidence retrieval. Answer correctness was evaluated separately.

Which retrieval method worked best?

On the 40 answerable development questions, BM25 reached 87.5% recall@5, the hybrid reached 82.5%, and the dense retriever reached 55%. The hybrid used reciprocal rank fusion with BM25 and a bge-small embedding model. I kept BM25 for this corpus.

Many questions used terms that appeared verbatim in the filings. That was a reason to start with a lexical baseline and measure whether adding embeddings helped.

Where the system still fell short

With BM25, recall@5 fell to 73.1% on the 67 answerable held-out questions. The project’s error analysis found a larger drop on table-lookup questions. Before tuning answer generation, I would inspect how captions and table headers are retained and whether retrieval brings back the relevant row with its units.

This was a prototype tested on one small financial corpus. The published results describe this evaluation setup.

How to apply the same check

Label the evidence for a small set of real questions, run BM25 as a baseline, and report retrieval recall separately from answer quality. Slice the results by question type so table misses don’t disappear inside an overall average.
